# Jev 飞书 Mac 伴随助手

独立的本机飞书伴随应用：识别前台聊天，经 `lark-cli` 只读最新消息或当前可见的历史片段，默认用本机 Ollama 生成六条可编辑、可复制的候选回复，也可显式配置 OpenAI / Anthropic 兼容回复服务。悬浮窗显示已确认的当前消息、Jev 意图与风险、简短回应要点；三个回复分组可分别从九种工作回复模式中选择。TypeSafe Jev 判断全局默认开启，可在设置中关闭。应用没有填入或发送功能。


**下载：[GitHub Releases](https://github.com/ai-freer/jev-feishu/releases)** · [更新记录](CHANGELOG.md) · [Mac 安装说明](packaging/INSTALL.zh-CN.md)

`0.3.0` 提供 Apple Silicon 的 DMG 安装包，内置 Python；终端构建工具仅开发者需要。飞书 CLI、用户授权和回复模型仍需自行配置。预发布包为临时签名，尚未通过 Apple 公证，Intel Mac 暂不支持。

主窗口可选择「跟随最新消息」或实验性的「跟随可见消息」。可见模式直接读取屏幕最后一个对方可见气泡的正文，不判断它是否为整个会话的最新消息，不依赖消息搜索。上下文最多取上方八条可见文字；底部半截气泡也保留为目标，辅助功能可能提供该气泡的完整正文。支持带引用标题和表情回应的普通文字；末尾是本人消息时向上寻找最近对方消息；最近对方消息无法读取正文时停读。可见内容变化会使旧结果失效，单纯位置变化不会反复打断生成。模式选择仅在本次运行有效，可随时切回最新模式。

**当前状态：开发原型，尚未完成正式首版验收。** 全局安装包的辅助功能授权、指定单聊识别、暂停恢复、虚构候选编辑/复制及设置连接测试已通过；普通群聊、单聊↔群聊切换和真实编辑/撤回等仍待实测。

## 运行条件

- macOS arm64；本项目开发环境使用 Python 3.12、`uv` 和 PyObjC。构建机需有 Rust `rustc`/`rust-lld` 与 macOS SDK。
- 飞书 Mac 客户端已登录；安装公开的 [`@larksuite/cli`](https://github.com/larksuite/cli)（官方安装命令：`npx @larksuite/cli@latest install`），完成用户身份配置与授权，确保本机可找到 `lark-cli`。开发验收使用 1.0.95；可通过 `lark-cli auth status --json --verify` 检查授权。
- 默认使用本机 Ollama（`127.0.0.1:11434`）和 `qwen3.5:4b`；模型不再限制为 4B/9B。设置中可修改本机地址、选择其他已安装模型，或显式选用 HTTPS 的 OpenAI / Anthropic 兼容服务。
- 云端 Jev 可继承 `~/.config/typesafe/env` 中的配置，也可在设置页填写仅本应用使用的地址、模型与密钥；配置文件须为 0600 权限，密钥不要提交到仓库。未配置 Jev 时回复服务仍可独立使用。
- 自动识别需要为 **`/Applications/Jev 飞书助手.app`** 授予 macOS 的 AX 窗口访问权限。在当前 macOS 27 中，路径是「系统设置 → 隐私与安全性 → 设备控制与数据访问」；较早的 macOS 版本通常列在「辅助功能」。这是读取飞书控件结构的权限，不是“屏幕录制”。只对 `/Applications` 中的安装包授权，不对 `dist/` 构建副本授权。

在本项目目录构建：

```bash
packaging/build_app.sh
bash packaging/install_app.sh
open "/Applications/Jev 飞书助手.app"
```

构建脚本在系统临时目录生成并签名独立应用，内置 Python 运行时，再发布到项目 `dist/build.noindex/` 并对发布产物的干净副本做严格签名复核；临时目录自动清理。构建副本放在 `.noindex` 目录，避免与 `/Applications` 中的正式应用一起出现在 Spotlight 搜索中。当本机恰有一个 Apple Development 签名身份时自动使用，以保持应用的系统权限身份稳定。没有可用身份时退回临时本机签名；有多个身份时须设置 `JEV_FEISHU_SIGN_IDENTITY` 指定证书。

当前项目位于受 macOS 文件提供者管理的 `Documents` 目录，系统可能给发布后的包重新附加 Finder 信息，使原位置的直接签名复核失败；安装脚本会复制到 `/Applications`、清理属性并再次严格验证。只使用 `/Applications/Jev 飞书助手.app` 进行日常运行和验收。

源码调试可用 `PYTHONPATH=src uv run --no-sync python -m jev_feishu.app`。应用默认暂停；打开飞书测试聊天后点「开始跟随」。只有当前窗口结构与 API 身份唯一匹配时才读消息。识别失败会停读并清空旧候选。菜单栏「Jev → 手动指定会话…」可用于主动联调，输入已确认的 `oc_…` 会话 ID 或 `ou_…` 用户 ID；它不是自动识别的替代验收。

启动器禁止向包内写入 Python 字节码缓存，以保持运行后的签名完整性；直接调用包内 Python 做开发检查时也需传入 `-B`。

从 Finder 启动时，应用会为飞书 CLI 的子进程补充其安装目录，使 NVM/Homebrew 安装的同目录 Node 可用；不会修改系统或终端的 PATH。

候选由用户明确配置的回复服务生成，默认是本机 Ollama；点击文本框可编辑，点击「复制」后仍需自行检查并在飞书发送。Jev 全局默认开启：开始跟随后，已可靠识别的普通文本聊天会将目标文本及最多前八条文本上下文发送至配置的 Jev 服务，默认经 OpenRouter 到 TypeSafe。设置页可全局关闭 Jev，不影响回复生成；关闭状态会保存并在重启后生效。未识别、暂停或可读取范围内只有本人消息时不触发 Jev。

通过主窗口模型菜单切换本次运行的回复模型或改变全局 Jev 开关会清空旧结果并重新读取当前消息。模型失败后可点击候选区「重试」，重新处理当前消息。

每个回复分组提供模式菜单，可选择“关闭此组”，至少保留一组。关闭组不请求模型，窗口随之折叠；三组选择保存到 `~/.config/jev-feishu/env`，下次启动沿用。切换后重新生成所有启用组，同一条消息已有成功的 Jev 判断时可复用，消息更新后重新判断。

判断与话术生成同时开始。回复采用流式接收，首条完整话术立即显示；每组两条，组间依次请求。某组失败不丢弃其他组，流式中断保留完整候选，失败位置显示“失败”。重试会重新生成所有启用组；后续候选或评分更新不会覆盖本轮已编辑的文字。

九种模式为：专业直接、高情商协作、轻松同事、这事我负责、向上同步、专业对客、高情商拒绝加班、霸道总裁、职场嘴替。默认三组为“专业直接 / 高情商协作 / 轻松同事”，悬停菜单可查看各模式说明。

“这事我负责”强调对事项的推进和结果负责：明确目标、协调依赖、同步风险、跟进结果；可以带人，也可以不带人，不默认管理权限，不替他人派活或承诺，也不把全部执行工作揽到自己身上。

每组上方候选是“简短回应”（通常 15–40 字），下方是“推进一步”（通常 30–80 字，复杂分工或边界说明可到 100 字）。长度是提示词目标，不会强行截断模型输出；长回复可在框内滚动、编辑并完整复制。两条应保持同一立场，不以夸张、编造事实或额外承诺制造差异。公共系统规则与当前模式指令独立于聊天输入；前文标注我与其他参与者；可见模式无法确认具体姓名时明确标记身份未确认，不把不同人默认视作同一人。模型输出仍需用户检查。

旧模式在读取配置时兼容映射：高情商话术→高情商协作、贴吧老哥→轻松同事、稳如老狗/简短直接→专业直接、拒绝加班→高情商拒绝加班、卑微乙方→专业对客、职场黑话→向上同步、阴阳怪气→职场嘴替、小组 Leader→这事我负责。保留三个位置及重复选择；读取不改写文件，下次保存模式时写入新名称。

关闭悬浮窗会暂停跟随，菜单栏应用继续运行。可通过「Jev → 显示悬浮窗」或在 Finder 中再次打开 `/Applications/Jev 飞书助手.app` 恢复窗口；恢复窗口不会自动开始读取。

配置文件是 `~/.config/jev-feishu/env`，首次启动以 0600 权限创建，默认 `JEV_FEISHU_REPLY_MODEL=qwen3.5:4b` 和 `JEV_FEISHU_JEV_ENABLED=true`；已有文件缺少新键时也默认为开启。未设置本应用覆盖项时，TypeSafe 配置从现有 `~/.config/typesafe/env` 只读取得，不自动复制共享密钥；飞书令牌由 `lark-cli` 管理。详见[隐私说明](PRIVACY.md)。

## 设置与排错

点击悬浮窗底部「设置…」或菜单栏「Jev → 设置与连接检查…」。设置页区分草稿和当前运行状态：

- **判断 · Jev**：编辑 HTTPS 服务地址、模型 ID、遮蔽密钥；未覆盖时继承共享 TypeSafe 配置。支持标准 `/v1/systemone` 和完整动作地址。
- **候选回复**：选择本机 Ollama、OpenAI 兼容或 Anthropic 兼容，填写该接口的地址、模型与密钥。Ollama 仅允许回环地址；其他远端服务必须用 HTTPS。
- **获取列表 / 手填模型**：从对应服务获取模型列表，也可直接输入模型 ID。列表不支持或不完整时保留手填值，不自动改选第一个模型。OpenRouter 的 Jev 列表只展示 TypeSafe 条目；别名可手填。完整 Jev `/evaluate`、`/decisions` 地址无法推导列表时会提示手填。
- **测试连接**：使用当前未保存表单，只发送固定虚构问候，不读取真实聊天、不保存配置。结果仅显示状态、候选数量和耗时。失败不会改走别的地址、服务商或密钥；HTTP 重定向被拒绝。
- **保存模型配置（重启生效）**：模型连接参数保存后须退出并重新打开应用，本次运行客户端不热切换。Jev 全局开关仍即时生效。原子保存为 0600，保留未编辑项及注释；外部修改会触发冲突提示，需重新打开设置。
- **密钥处理**：输入框不回填已有密钥，留空保留，填写新值才替换，勾选“清除密钥”才清除（Jev 清除会屏蔽共享密钥继承）。更换服务地址/协议时不静默复用旧密钥，须重新填写或明确清除。共享 TypeSafe 文件始终不被本应用写入。
- **远端回复提示**：切换到远端回复地址时，保存前会再次确认目的地。重启并开始跟随后，聊天文本及上下文将发往该服务；关闭 Jev 判断不会关闭远端回复。

本应用配置键为 `JEV_FEISHU_REPLY_PROVIDER`（`ollama` / `openai` / `anthropic`）、`JEV_FEISHU_REPLY_BASE_URL`、`JEV_FEISHU_REPLY_MODEL`、`JEV_FEISHU_REPLY_API_KEY`，及 `JEV_FEISHU_TYPESAFE_BASE_URL`、`JEV_FEISHU_TYPESAFE_MODEL`、`JEV_FEISHU_TYPESAFE_API_KEY`。旧配置缺少这些项时保持原来的本机默认和共享 Jev 继承，不会自动改走云端回复。

打开设置会暂停跟随。启动只检查飞书用户授权和本机 Ollama 模型清单；已配置的远端回复服务不会自动查询列表或测试。飞书联网授权检查最多等待 30 秒，期间主按钮显示“检查中…”。检查失败时保留原因并提供“重新检查”；成功后恢复“开始跟随”，仍需用户手动点击。关闭设置后也不会自动开始读取。

读取错误会清空已有候选；当前消息为本人发送、已撤回或没有可处理普通文本时显示对应状态。界面失去飞书当前聊天身份时停止读取，不以旧候选代替新会话结果。

内外部账号同名时，识别会结合标题身份标记和 API 的跨租户属性。内部身份只在完整识别到已支持的中文桌面标题栏布局（支持有导航标签和无导航标签的标题与操作区）且标签区域读取完整时确定；不能仅因任意位置没找到“外部”字样就排除外部联系人。控件结构变化、读取失败、API 属性缺失、分页未完成或同一侧仍有多个同名候选时继续停读，不按近期联系顺序猜测。

## 开发验证

发布包由 `bash packaging/release_macos.sh` 生成到 `dist/releases.noindex/`，使用临时签名避免包含开发者个人证书，同时生成 SHA-256。应用版本取自 `src/jev_feishu/__init__.py`，需与 `pyproject.toml` 一致；通过 Git 标签、GitHub Release 和 CHANGELOG 跟踪版本。

```bash
PYTHONPATH=src uv run --no-sync python -m unittest discover -s tests -v
PYTHONPATH=src uv run --no-sync python -m compileall -q src
codesign --verify --deep --strict "/Applications/Jev 飞书助手.app"
```

测试使用虚构消息和模拟 CLI/HTTP 响应；完整测试不会读取真实聊天。以上命令在仓库根目录运行。上游来源见[来源说明](docs/upstream.md)。

构建并安装后，还可检查实际安装模块的虚构完整链路：

```bash
"/Applications/Jev 飞书助手.app/Contents/MacOS/JevFeishuPython" -B tests/manual_hud_fixture.py --check
```

去掉 `--check` 可打开标有「虚构验收」的原生悬浮窗及测试控制台，模拟单聊/群聊切换、编辑、撤回、模型故障和授权失效。该脚本仅替换外部 CLI/HTTP 与前台观察输入，运行安装包中的正式模块，不读取真实聊天、配置密钥或调用网络。`--check` 只证明包内模块链路，不能代替真实前台识别、原生交互或正式验收。

用同一包内 Python 执行 `-B tests/measure_installed_replies.py`，可用固定虚构消息分别测量 4B/9B 两次完整六候选生成；它调用真实本机 Ollama，只输出耗时、数量、错误类别及请求前后的模型驻留状态。不会主动卸载共享模型，首轮是否包含加载以实际驻留状态为准。

上下文规则：判断和回复均使用合计最多 8 条上下文消息（含目标之后的本人消息），保留发言者与时间顺序。前文及其引用合计最多 8,000 字符，每条正文最多 2,000 字符；目标正文最多 8,000 字符、目标引用最多 2,000 字符，截断显式标记。可见模式仅用屏幕上可读取的内容，不自动补取不可见历史；API 模式用稳定匿名参与者标签区分发送者。引用不等同于当前发言。

0.2.2：末尾本人消息不再直接停读，回溯最近对方消息并显示“你已回复”。后续本人消息按从旧到新单列，优先保留最近 8 条、每条最多 1,000 字符，与此前消息共用 8 条及 8,000 字符预算。候选生成后，开启 Jev 时会额外发送结构化上下文及六条候选至同一 Jev 服务，获取相对推荐度；关闭 Jev 不评分。分数不是事实正确率，失败显示未评分；评分不会覆盖用户编辑。
